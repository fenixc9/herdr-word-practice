# 设计说明

这份文档记录「为什么做成这样」，而不是「有哪些功能」——功能看 README。

## 1. 场景决定了形态

约束不是「要有一个背单词软件」，而是「vibe coding 的间隙背几个词」。这个场景有四条硬约束：

1. **时间短且不可预测。** agent 可能 40 秒后就需要你，也可能 20 分钟。
2. **注意力是残留的。** 刚从一堆代码里抬头，没法一次消化一屏信息。
3. **不能污染工作区。** 不能占掉一个 pane、不能改布局、不能让我回来时找不到光标。
4. **中断必须无痛。** 如果退出会丢进度，那就不敢在「可能随时被打断」的时候打开它。

由此得到：

| 约束 | 设计 |
| --- | --- |
| 时间短 | 一组默认 10 词，约 90 秒；随时 Esc 走人，进度即时落盘 |
| 注意力残留 | 一屏只有一张卡；标题栏就是全部导航 |
| 不打扰 | 当前 tab 内 split 一小块，Esc 即收（40ms），不切 tab |
| 中断无痛 | 每次作答立刻写入（不是退出时才写） |

第 4 点值得展开：`session.py` 的 `on_answer` 回调在每答完一个词时就把状态写进
`progress.json`。所以哪怕进程被 kill，已经答过的题都算数——只丢当前这一张卡。
这点在 `tests/test_tty.py` 里是真跑一遍 pty 验证的，不只是单测函数。

## 2. 为什么是打字，而不是选择题

TypeWords 的核心是「敲出来」。这里保留这一点，原因是判分信号的质量：

- 选择题答对，可能是排除法、可能是熟悉感错觉；
- 打出来，才是真的能从记忆里重构。

代价是「输入灵活性差」——错一个字母就判错。所以做了三个补偿：

1. **自动提交**：拼完立刻判，不用按回车，减少一次判断开销。
2. **提示键（Tab）**：卡住时逐个字母要提示；用过提示仍然算对，但 quality 封顶 3
   （对应 SM-2 里的 "hard"），间隔涨得慢。既保住了流畅感，也不让提示变成免费午餐。
3. **判错之后立刻给全貌**：正确拼写、你输入的内容、近义词一起显示。错误是最强的记忆锚点，
   前提是当场看到正确答案。

自测模式（`selfcheck`）是唯一的例外：不打字，按 1–4 自评。理由是场景——通勤、开会、
一只手在鼠标上时，仍然可以复习，只是判分交给自己的诚实。自评映射到 quality 1/3/4/5。

## 3. 一张卡的取舍

卡片从上到下：词（或遮罩）/ 音标 + 词性 / 中文释义 / 例句 / 例句翻译 / 输入框 / 长度提示。
自测模式把输入框换成 `1 不认识 2 模糊 3 认识 4 太简单`。

几个具体决定：

- **长度提示用下划线而不是横线**，并且保留空格和连字符：`re-run` → `_ _ - _ _ _`。
  这样它既是提示又不是白给。
- **默写模式遮罩单词，但保留音标和词性。** 音标是线索不是答案；不给音标的话，
  难度会在「记不住拼写」和「记不住发音」之间混在一起，就没法判断到底哪儿没记住。
- **例句挖空用 `______`，且只挖第一个匹配。** 挖多个会让例句读不懂，
  而例句的价值就在于「读懂它、从而想起那个词」。
- **答对时 `✓ 正确 · 一次拼对`**，用了提示则写 `用了 N 个提示`。
  差别写出来，用户才知道那个词其实还不牢。
- **状态栏常驻**：进度条、正确率、今日 x/y、计时、静音图标。
  `今日 12/20` 是唯一一个「跨会话」的数字，用来给一点温和的推力。

布局对高度是自适应的：小窗格里先丢空行（`_fit`），保证状态栏和按键提示永远可见；
只有当卡片本身比窗口还高时才截断内容。

## 4. 记忆曲线：为「碎片」调过的 SM-2

标准 SM-2 的步进是 1 天 / 6 天 / 之后按 ease 增长。对每天打开一次的 App 合适，
对「一天打开五次」的场景太慢——第一次学完要等一整天才有反馈。

这里的调整：

```python
LEARNING_STEP  = 10 分钟      # 第一次答对
SECOND_STEP    = 1 天         # 第二次答对
interval      *= ease         # 之后
ease           = 2.5 起, 答对 ±(0.1 - (5-q)*0.08), 答错 -0.2, 夹在 [1.3, 2.8]
MASTERED       = 间隔 ≥ 21 天 且 reps ≥ 4
```

于是同一天里可以自然形成「学 10 个新词 → 写两小时代码 → 这 10 个词回来复习」的循环，
正好贴合 vibe coding 的节奏。答错的词 10 分钟后再来一次，也在同一段工作里闭环。

`smart` 模式的取词顺序因此是：

1. 到期的（`due <= now`），按到期时间排；
2. 学习中的（还没到期，但正在 10 分钟/1 天的阶梯上）；
3. 错过的但没到期的（`wrong > 0`），错得多的优先；
4. 新词，受 `daily_new_limit` 限制（默认 8）。

新词预算按组大小的 40% 取，且不超过当天剩余额度——这样一组里既有复习也有新词，
但不会某天一口气灌 50 个新词然后全部忘掉。

## 5. 展示形式：为什么是终端，为什么是这套配色

herdr 的插件能给的界面就是「一个 pane」。所以这不是「要不要做 GUI」的选择，
而是「在这块字符画布上怎么让人愿意看 90 秒」。

- **圆角边框 + 细分隔线**（`╭ ╮ ╰ ╯ ├ ┤`）给一个明确的「这是一个临时面板」的信号。
- **标题栏左右分置**：左边是名字和模式（我现在在干什么），右边是 `3/10` 和 🔥streak
  （我进行到哪了）。视线不用移动就能拿到两件事。
- **单词居中加粗**，字号靠终端字体，视觉重心只有一个。
- **颜色语义固定**：绿=对，红=错，桃色=提示/警示，蓝=今日进度，灰=次要信息。
  24-bit 优先，退到 256 色，再退到无色（`NO_COLOR` 也认）。
- **输入框内联高亮**：已输入字符与目标前缀匹配时显示绿色，第一个不匹配处开始变红。
  这样在按下回车之前就知道自己错了——比打完了才知道更省时间。
- **同步输出**（`\x1b[?2026h`）+ 交替屏幕：避免闪烁和滚动残影，退出时原样恢复终端。

## 5.1 为什么用 split 而不是 popup

最初做的是 popup（悬浮、不占布局，观感更「临时」）。实测下来 popup 的关闭很迟钝：
按 Esc 后进程 40ms 就退出了，但 popup 留在屏幕上 1 秒以上才消失——而同样的代码放在
`split` 里，「Esc → 窗格消失」是 40ms。

对一个「随时打开、随时关掉」的碎片工具，**消失得快**比**浮在上面**重要得多，
所以默认改成 split。要看 popup 版本，把 manifest 里 `break` 的 `placement` 改回
`popup` 并加 `width`/`height` 即可。

## 6. 在 herdr 生态里的位置

- **动作没有 PTY。** 这是最容易踩的坑：`[[actions]]` 里直接跑 TUI 会报
  "Device not configured"。所以每个交互动作都走 `main.py open-pane …`，
  由它调用 `herdr plugin pane open`，真正带 PTY 的进程由 herdr 拉起。
- **事件要挑合法的。** herdr 0.9.x 对未知事件名只告警不报错，很容易写出「看起来注册了但永远不触发」
  的 hook。`agent.idle` 就是这样一个陷阱；合法的是 `pane.agent_status_changed`，
  状态在 payload 里。
- **提醒是「提议」不是「打断」。** 事件处理器只发一条通知，不抢焦点、不自动开窗格
  （要自动开得显式设 `nudge.auto_open = true`）。节流 45 分钟 + 静默时段 23:00–08:00，
  且今日目标已达成、没有到期词时不提醒。
- **状态目录用 herdr 注入的路径**（`HERDR_PLUGIN_STATE_DIR` / `HERDR_PLUGIN_CONFIG_DIR`），
  回退到 XDG。这样插件被 unlink 再 link 也不会丢进度。

## 7. 明确不做的

- **不做账号/云同步。** 一个只有本地 JSON 的工具才敢让人随时打开。
- **词库分两层。** 大纲词表（CET-4 4537 / CET-6 2271）来自公开数据源，负责"覆盖全"；
  例句/近义词/搭配/词源是手写的，负责"记得住"。手写部分和生成部分分开存放
  （`data/wordbooks/curated/` 对手写层，`*.tsv` 对生成层），重跑生成脚本不会丢手写内容。
- **不做排行榜/打卡社交。** 会引入「今天没背就失败了」的压力，而这个工具的前提是「随时可以不来」。
- **不在 Windows 上硬凑。** manifest 只声明 linux/macos，而不是声称支持却没测过。

## 8. 失败时会怎样

- `progress.json` 损坏 → 备份成 `progress.corrupt-<ts>.json`，从空状态继续（不阻塞启动）。
- 没有 TTS → `doctor` 里标 `fail`，练习时静默，不报错。
- 词书里有重复词/缺释义 → 解析阶段直接报行号，而不是运行时随机崩。
- 环境没有 tty（比如从 action 直接调用）→ `drill` 渲染一帧后退出，而不是卡住。
- 自定义词书被删了但设置里还记着 → 回退到第一本可用词书；但如果你显式 `-b nope`，会明确报错。
